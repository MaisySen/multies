## Android release signing

The upload keystore lives outside the repo (path, alias and passwords: CREDENTIALS.local.md,
"Android upload keystore (round 9)"; the owner has a backup copy). It is never committed:
`*.jks`, `*.keystore`, `credentials.json` and `secrets/` are in `.gitignore`.

`android/` is generated by `npx expo prebuild`, so signing is added by a config plugin,
`plugins/with-release-signing.js` (listed in `app.json`). On every prebuild it writes a
`signingConfigs.release` block into `android/app/build.gradle` that reads four values from Gradle
properties or environment variables of the same name:

```properties
# ~/.gradle/gradle.properties (never in the repo)
MYMAIL_UPLOAD_STORE_FILE=/absolute/path/to/mymail-upload-keystore.jks
MYMAIL_UPLOAD_STORE_PASSWORD=...
MYMAIL_UPLOAD_KEY_ALIAS=mymail-upload
MYMAIL_UPLOAD_KEY_PASSWORD=...
```

Release builds then sign with that key (APK schemes v2 and v3). Without the values a local release
build falls back to the debug key and prints a warning; `-PmymailRequireUploadKey=true` turns that
into an error, which the commands below use.

### Build locally

```bash
export ANDROID_HOME=$HOME/Android/Sdk
npx expo prebuild --platform android --clean --no-install
cd android
# Play bundle (all phone ABIs)
./gradlew bundleRelease -PreactNativeArchitectures=arm64-v8a,armeabi-v7a,x86_64 -PmymailRequireUploadKey=true --no-daemon
# Direct install APK for modern phones
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a -PmymailRequireUploadKey=true --no-daemon
```

Outputs: `android/app/build/outputs/bundle/release/app-release.aab` and
`android/app/build/outputs/apk/release/app-release.apk`.

### Check the builds

```bash
BT=$ANDROID_HOME/build-tools/37.0.0
java -jar bundletool.jar validate --bundle=app-release.aab
java -jar bundletool.jar build-apks --bundle=app-release.aab --output=app.apks \
  --ks=$MYMAIL_UPLOAD_STORE_FILE --ks-pass=pass:... --ks-key-alias=mymail-upload --key-pass=pass:...
keytool -printcert -jarfile app-release.aab         # SHA-256 must match the keystore
$BT/apksigner verify --verbose --print-certs app-release.apk
$BT/aapt dump badging app-release.apk | grep -E "package|targetSdk|debuggable"
```

bundletool comes from github.com/google/bundletool/releases (Apache 2.0).

### Build with EAS instead

EAS keeps its own copy of the keystore. To use ours rather than one EAS makes, create
`credentials.json` next to `eas.json` (gitignored, never committed):

```json
{
  "android": {
    "keystore": {
      "keystorePath": "/absolute/path/to/mymail-upload-keystore.jks",
      "keystorePassword": "...",
      "keyAlias": "mymail-upload",
      "keyPassword": "..."
    }
  }
}
```

Then `npx eas-cli build -p android --profile production-local-credentials`, or upload it once with
`npx eas-cli credentials` (Android, production, Keystore, upload) and use `--profile production`.

### Play App Signing

On the first upload, accept Play App Signing. Google holds the app signing key; our keystore is the
upload key. If the upload key is ever lost, Play support can reset it, so keep the backup safe.

## iOS

```bash
npx eas-cli login
npx eas-cli init                                   # writes extra.eas.projectId into app.json
npx eas-cli build -p ios --profile production      # cloud build, no Mac needed
npx eas-cli submit -p ios --profile production --latest
```

The first iOS build asks for the Apple ID once and creates the certificate and provisioning
profile. Fill the `OWNER_FILL_IN_...` values in `eas.json` (`submit.production.ios`) for
non-interactive submits.
