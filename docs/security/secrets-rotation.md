# Secrets rotation

Every secret MyMail uses, where it lives, and how to rotate it without downtime. Rotate on this schedule, immediately when someone with access leaves, and immediately after any suspected leak.

Set a secret on Cloudflare with `npx wrangler secret put NAME` (production) or `npx wrangler secret put NAME --env staging`. Setting a secret deploys a new version of the Worker straight away.

| Secret | Where | Rotate | Impact of rotation |
| --- | --- | --- | --- |
| `APP_SECRET` | Cloudflare (both environments) | Yearly, or on leak | Signs sessions and encrypts stored secrets. See below. |
| `STRIPE_SECRET_KEY` | Cloudflare | Yearly, or on leak | None if done in order. |
| `STRIPE_WEBHOOK_SECRET` | Cloudflare | On leak | Webhooks fail until both sides match. |
| `RESEND_API_KEY` | Cloudflare | Yearly, or on leak | None if done in order. |
| `RESEND_WEBHOOK_SECRET` | Cloudflare | On leak | Delivery events fail until both sides match. |
| `AUTH0_CLIENT_SECRET` | Cloudflare | Yearly, or on leak | SSO sign-in fails until updated. |
| `SENTRY_DSN_API`, `SENTRY_DSN_WEB` | Cloudflare | On abuse only | DSNs are public by design. |
| `CLOUDFLARE_API_TOKEN` | GitHub Actions secret | Every 6 months | CI deploys fail until updated. |
| `SENTRY_AUTH_TOKEN` | GitHub Actions secret | Every 6 months | Releases and source maps stop uploading. |
| `DEPLOY_TOKEN` | Preview host build | On leak | Preview migrations fail until rebuilt. |
| `BACKUP_AGE_RECIPIENT` / private key | GitHub variable / offline | Yearly | Old backups need the old private key. |
| Stalwart admin password | Mail server host | Yearly, or on leak | MyMail cannot provision until updated. |

## General order (no downtime)

1. Create the new value at the provider. Most providers allow two live keys at once (Stripe "roll key" with an expiry, Resend and Sentry tokens, Cloudflare tokens).
2. Set it on staging, run `scripts/smoke.sh https://mymail-staging.mymail-app.workers.dev`, then set it on production and run the smoke test there.
3. Revoke the old value at the provider.
4. Record the date in the team's secrets register (never the value).

## Stripe

1. Dashboard, Developers, API keys, the restricted key, "Rotate key". Choose an expiry for the old key (for example 1 hour).
2. `npx wrangler secret put STRIPE_SECRET_KEY` (staging, then production).
3. Check Settings, Billing loads and a test checkout opens.

For the webhook secret: Developers, Webhooks, the endpoint, "Roll secret" (Stripe keeps the old one valid for up to 24 hours), then `wrangler secret put STRIPE_WEBHOOK_SECRET`.

## Resend

Create a new API key, set `RESEND_API_KEY`, send a test from Settings, then delete the old key. For the webhook secret, recreate the webhook endpoint and set `RESEND_WEBHOOK_SECRET`.

## Auth0

Applications, MyMail, Settings, "Rotate" the client secret, then set `AUTH0_CLIENT_SECRET` straight away; SSO sign-in fails between the two steps, so do it at a quiet time.

## APP_SECRET

`APP_SECRET` signs session cookies and derives the key that encrypts webhook signing secrets and similar values at rest. Changing it signs everyone out and makes stored encrypted values unreadable. Rotate it only with a planned window:

1. Announce a short maintenance window.
2. Export the encrypted values you need to keep (webhook endpoint secrets): they can be regenerated by each workspace from Settings, Developers instead.
3. `npx wrangler secret put APP_SECRET` with 48 or more random characters (`openssl rand -base64 48`).
4. Ask workspaces to roll their webhook signing secrets, or roll them for them and notify.

## GitHub Actions secrets

Repository, Settings, Secrets and variables, Actions. Replace `CLOUDFLARE_API_TOKEN` with a new token that has the same scopes (Workers Scripts edit, D1 edit, Workers Routes edit, Email Routing edit, Account Settings read), run the CI workflow, then revoke the old token in Cloudflare.

## After a leak

Treat it as an incident ([runbooks/incident.md](../runbooks/incident.md)): rotate the leaked value first, then check provider logs for use of the old value, then write the postmortem.
